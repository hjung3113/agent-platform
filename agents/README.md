# Agent Surface

Only human/LLM reasoning roles live here.

Deterministic system actors such as Kernel, Harness Host, Scheduler, Context Compiler,
admission service, and state projection are product code, not agent personas.

## Canonical surfaces

- `roles/` — responsibility and permission envelopes
- `skills/` — reusable discipline/workflow knowledge
- `commands/` — thin user-invoked routing wrappers
- `workflows/` — role composition templates

## Rule and hook boundary
Rules and hooks are integration/control surfaces, not reasoning roles and not alternative workflow authorities.

- **Rule** — declarative guidance or constraint surfaced to an admitted runtime/context. A rule cannot create authority, widen capability, or override Kernel/Human policy merely because a runtime loads it automatically.
- **Hook** — deterministic lifecycle/tool automation executed by the Host/platform around admitted events. A hook may observe, validate, transform derived deployment output, or propose candidates within its admitted capability envelope, but it cannot independently publish authoritative run state, authorize external effects, or widen permissions.

Runtime-native hook/rule mechanisms may be generated by adapters, but their effective identity/version and behavior-relevant configuration are part of runtime capability/drift control. Do not introduce dedicated repository directories until an independent lifecycle or ownership boundary requires them.

## Invocation taxonomy

Adopt Matt Pocock's useful distinction:
- **user-invoked**: explicit human entry point; orchestration-oriented; zero model auto-routing need
- **model-invoked**: reusable discipline the model may reach automatically

When user-invoked surfaces grow, route through a small namespace/router layer rather than
exposing every command description in every context.
